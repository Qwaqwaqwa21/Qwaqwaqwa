# GeoLog — руководство пользователя

Пошаговая инструкция по работе с GeoLog для геолога / петрофизика. Описывает
реально существующий в интерфейсе функционал: как его открыть, что он делает,
какие данные нужны и какая роль требуется. Названия разделов и кнопок в
инструкции соответствуют подписям на экране (на русском — там, где интерфейс
русский; часть служебных панелей в этой сборке подписана по-английски, это
отмечено отдельно).

> Важно: в этой сборке GeoLog верхнее меню намеренно сокращено до тех разделов,
> которые реально используются в работе (оцифровка, QC, охват, корреляция,
> отбивки, статистика, дашборд). Ещё несколько десятков панелей (петрофизика,
> кроссплоты, фации, сейсмика и т. п.) остаются в коде и доступны через
> палитру команд (`Ctrl/Cmd+K`) или цифровые клавиши `1`–`9` — см. раздел
> [14](#14-зоны-петрофизика-и-шаблоны) и [23](#23-горячие-клавиши).

## 1. Начало работы: запуск и первый вход

### 1.1 Запуск сервера

Один из трёх вариантов (все запускают один и тот же сервер на `http://localhost:8000`):

**А. Скрипт `run.sh` (проще всего)**
```bash
chmod +x run.sh
./run.sh
```
Скрипт сам проверит версию Python (нужен 3.9+), поставит зависимости из
`requirements.txt` и запустит сервер.

**Б. Docker**
```bash
docker compose up --build
```

**В. Вручную**
```bash
python3 -m pip install -r requirements.txt
python3 -m uvicorn backend.main:app --host 0.0.0.0 --port 8000 --reload
```

После запуска откройте в браузере **http://localhost:8000** — загрузится
интерфейс GeoLog. Техническая документация API (Swagger) доступна на
`http://localhost:8000/docs`.

### 1.2 Первый вход

При первом открытии в браузере нет ни одного проекта. GeoLog создаёт пустую
рабочую область; дальше нужно:

1. Создать проект (раздел [3.1](#31-создание-и-переключение-проекта)).
2. Добавить скважину (раздел [3.2](#32-добавление-и-редактирование-скважины)).
3. Загрузить LAS-файл (раздел [4](#4-загрузка-данных-las-dlis-lis)).

Если сразу нажать **Upload LAS** без созданного проекта/скважины — GeoLog
создаст проект «My Project» и скважину «New Well» автоматически и загрузит
файл в неё; после этого её можно переименовать через **Edit Well** (раздел
[3.2](#32-добавление-и-редактирование-скважины)).

### 1.3 Активная роль по умолчанию

В правом верхнем углу есть выпадающий список ролей (`viewer` / `interpreter`
/ `admin`) — это не логин, а переключатель того, с какой ролью браузер
обращается к API (см. раздел [2](#2-роли-и-права-доступа)). **При первом
открытии в новом браузере активная роль — `admin`** (без предварительной
авторизации), поэтому по умолчанию доступны все действия. Выбор роли
сохраняется в этом браузере (localStorage) между сессиями.

## 2. Роли и права доступа

GeoLog использует упрощённую ролевую модель без логина/пароля: активная роль
выбирается вручную в выпадающем списке `viewer / interpreter / admin` в
верхней панели, и это значение отправляется на сервер в заголовке
`X-User-Role` при каждом запросе. Сервер сам проверяет права независимо от
интерфейса — если попытаться выполнить действие выше своей роли, запрос
будет отклонён с ошибкой 403, даже если кнопка в интерфейсе оказалась
активна.

**Как сменить роль:**
1. В верхней панели найдите выпадающий список рядом с логотипом (`viewer` /
   `interpreter` / `admin`).
2. Выберите нужную роль — появится уведомление «Active role: …».
3. Кнопки, требующие более высокой роли, автоматически становятся
   полупрозрачными и неактивными (наведите курсор — в подсказке написано,
   какая роль нужна).

Иерархия ролей: `admin` > `interpreter` > `viewer` — более высокая роль
включает все права более низкой. Подробная таблица — в разделе
[20](#20-права-ролей--сводная-таблица).

### 2.1 Блокировка скважины (Locked)

Если скважина **подписана** (см. раздел [18](#18-подпись-sign-off-и-экспорт)),
любые изменения данных этой скважины (кроме операций со снапшотами и
просмотра статуса блокировки) для ролей `viewer`/`interpreter` блокируются
сервером с ошибкой 423 «well is locked by approved snapshot». Роль `admin`
может продолжать вносить изменения даже в подписанную скважину.

## 3. Проекты и скважины

### 3.1 Создание и переключение проекта

**Требуется роль admin.**

1. В левом сайдбаре нажмите иконку папки со плюсом рядом с заголовком
   **WELLS** (New Project).
2. Введите название проекта → OK.
3. Проект появится в списке в сайдбаре.

**Переключение между проектами:** кликните по названию нужного проекта в
списке — активный проект помечается зелёной полосой слева и точкой «●»
перед названием, список скважин под ним подгружается автоматически.

**Удаление проекта:** нажмите иконку корзины у названия проекта, введите
`DELETE` для подтверждения — удалятся **все** скважины и данные проекта.

### 3.2 Добавление и редактирование скважины

**Добавление — требуется роль admin.**

1. Нажмите **Add Well** внизу сайдбара (или иконку "+").
2. Введите название скважины и, при наличии, UWI/API-номер.
3. Скважина появится в списке под текущим активным проектом.

Скважину также можно создать автоматически при массовой загрузке LAS-файлов
(см. [4.3](#43-массовая-загрузка-bulk-import-wizard)) — по значению
`WELL.NAME` внутри самого LAS-файла.

**Редактирование метаданных — требуется роль interpreter или admin** (эндпоинт
относится к обычным операциям записи):
1. Выберите скважину в сайдбаре, чтобы она стала активной.
2. В шапке скважины откройте выпадающее меню **Data** → **Edit Well**.
3. Доступны для правки поля: название, UWI/API-номер, оператор, площадь
   (Field Name), единицы глубины (FT/M).
4. Сохраните.

> Координаты скважины (широта/долгота) в этой форме не редактируются вручную
> — они заполняются автоматически из заголовка LAS-файла при загрузке (если
> в нём есть соответствующие параметры локации). Увидеть скважины на карте по
> координатам можно через палитру команд `Ctrl/Cmd+K` → **Map**.

**Поиск скважины:** поле «Search wells…» под заголовком сайдбара фильтрует
список скважин текущего проекта по названию и метаданным в реальном времени.

**Удаление скважины — требуется роль admin:** иконка корзины рядом со
скважиной в списке (если она видна) или через API; подтверждение — ввести
`DELETE`. Удаляются все рейсы и данные скважины без возможности восстановления.

## 4. Загрузка данных: LAS, DLIS, LIS

### 4.1 Загрузка одного файла

1. Выберите скважину в сайдбаре (или, если скважина ещё не выбрана — GeoLog
   создаст скважину/проект по умолчанию).
2. Нажмите **Upload LAS** (кнопка в верхней панели или в шапке скважины,
   либо `Ctrl/Cmd+U`) — для DLIS/LIS откройте выпадающее меню **Data** в
   шапке скважины и выберите **Upload DLIS** / **Upload LIS**.
3. Выберите файл в диалоге ОС.
4. После загрузки появится уведомление: имя файла, число созданных рейсов
   (для DLIS/LIS часто больше одного), число кривых и точек по глубине.

Файл добавляется как **новый рейс (log run)** к выбранной скважине — старые
рейсы не удаляются и не перезаписываются, они остаются в выпадающем списке
рейсов (`Select log run…`) в шапке скважины.

**Поддерживаемые форматы:**
- **LAS 2.0/3.0** — парсер понимает как пробельно-, так и запятая-
  разделённые варианты, автоматически определяет кодировку (UTF-8, CP1251,
  CP866 и др.), поэтому кириллические мнемоники (ГК, ПС, НГК, БК, ГГКп, АК,
  ДС, МК и т. д.) читаются корректно.
- **DLIS** — один файл может содержать несколько кадров/рейсов; каждый
  становится отдельным рейсом скважины.
- **LIS** — аналогично, один или несколько наборов логов на файл.

**Ограничения:**
- максимальный размер файла — **50 МБ** (иначе ошибка 413 «File too large»);
- пустой файл отклоняется (ошибка 400 «Empty file»).

**Невалидный файл отклоняется, а не создаёт пустую запись.** Если файл имеет
расширение `.las`, но не содержит блока `~ASCII` с данными по глубине (то
есть фактически не является LAS-файлом), сервер вернёт ошибку **400 «No
curve data found in file — not a valid LAS file»**, и никакого рейса создано
не будет — ни с 0 точками, ни «призрачного». То же для DLIS/LIS — при ошибке
разбора или отсутствии кадров/данных сервер вернёт `400` и рейс не создастся.

### 4.2 Многорейсовые скважины

Каждая новая загрузка LAS/DLIS/LIS для одной и той же скважины добавляет
рейс с новым порядковым номером (`Run 1`, `Run 2`, …). Выбрать активный рейс
для просмотра/экспорта можно в выпадающем списке **Select log run…** в шапке
скважины — рядом с каждым рейсом показан:
- значок статуса оцифровки (⏳ ожидает проверки / ✅ принят / ❌ отклонён),
- номер рейса, имя файла, число точек, версия/формат (LAS/DLIS/LIS),
- пометка, если рейс является переоцифровкой другого (`↩ redo of Run N`) или
  сам уже переоцифрован (`→ fixed in Run N`).

### 4.3 Массовая загрузка (Bulk Import Wizard)

Для загрузки сразу многих LAS-файлов (в том числе на разные скважины):

1. Нажмите **Bulk Import** в верхней панели.
2. В открывшемся окне либо:
   - перетащите файлы/папку в область (папки сканируются рекурсивно, со
     всеми вложенными подпапками);
   - нажмите **Select Files** (выбор нескольких `.las`-файлов) или
     **Select Folder** (выбор целой папки).
3. GeoLog обработает каждый файл по очереди:
   - прочитает поле `WELL.` из самого LAS-файла, чтобы определить имя
     скважины;
   - если скважины с таким именем ещё нет в активном проекте — создаст её
     автоматически;
   - если скважина уже есть (сравнение имени без учёта регистра) — добавит
     файл как новый рейс к ней;
   - для каждого файла показывается прогресс-бар и статус
     (PENDING → PARSING → UPLOADING → DONE/ERROR).
4. По завершении — сводка: сколько скважин создано, сколько файлов
   загружено, сколько ошибок.

Приняты только файлы с расширением `.las`; файлы, не прошедшие валидацию на
сервере (см. [4.1](#41-загрузка-одного-файла)), помечаются статусом `ERROR`
с текстом ошибки, но не останавливают загрузку остальных файлов из пакета.

## 5. Проверка оцифровки (digitization review)

Каротаж в этом проекте оцифровывается внешней группой по бумажным/сканированным
первоисточникам и загружается как LAS/DLIS/LIS. Прежде чем такому рейсу можно
доверять (использовать для интерпретации и тем более для экспорта клиенту),
его нужно свериться со сканом оригинала и явно принять или отклонить.

### 5.1 Статусы

Каждый новый рейс при загрузке получает статус **`pending_review`**
(⏳, «ожидает проверки»). Дальше он может перейти в:
- **`accepted`** (✅) — рейс сверен со сканом и соответствует ему,
- **`rejected`** (❌) — рейс не соответствует скану, нужна переоцифровка.

### 5.2 Прикрепление скана и проверка рейса

1. В шапке скважины выберите нужный рейс в **Select log run…**.
2. Нажмите **📎 Upload Scan** и выберите файл скана оригинала (PDF или
   изображение).
3. После загрузки станет доступна кнопка **🔍 View Scan** — открывает скан в
   новой вкладке для визуального сравнения с оцифровкой.
4. Сверив данные, нажмите:
   - **✅ Accept** — если рейс соответствует скану;
   - **❌ Reject** — если не соответствует; появится окно, куда нужно
     вписать причину (что именно не совпадает) — это обязательное текстовое
     поле, оно сохраняется в примечаниях к рейсу.

**Требуется роль interpreter или admin.** Загрузка скана и решение
accept/reject недоступны роли `viewer`.

### 5.3 Переоцифровка отклонённого рейса (redo-of)

Если рейс отклонён, оцифровщики присылают новый файл — он загружается как
**новый, отдельный** рейс (см. [4.1](#41-загрузка-одного-файла)); формальной
связи между старым и новым рейсом при этом не возникает автоматически, её
нужно указать вручную:

1. Загрузите исправленный файл как обычно (Upload LAS/DLIS/LIS) — появится
   новый рейс со статусом `pending_review`.
2. Выберите этот новый рейс в **Select log run…**.
3. Рядом с кнопками Accept/Reject появится блок **🔗 Это переоцифровка
   рейса…** — раскройте список и выберите тот отклонённый рейс, который этот
   новый файл исправляет (в списке — только отклонённые рейсы этой же
   скважины, ещё не связанные с другой переоцифровкой).
4. Нажмите **Link**.

После связывания старый (отклонённый) рейс перестаёт считаться «зависшей»
проблемой при подсчёте готовности скважины к сдаче — вместо него
учитывается новый рейс, который нужно будет так же принять/отклонить по
результатам сверки со сканом.

### 5.4 Значение для остальных функций

- **Экспорт** (LAS/пакет) блокируется, пока в числе экспортируемых
  (крупнейших по числу точек) рейсов остаются рейсы со статусом
  `pending_review` или необработанные `rejected` — подробнее в разделе
  [18](#18-подпись-sign-off-и-экспорт).
- **Виджет готовности** в шапке скважины (раздел
  [17](#17-сводка-готовности-скважины)) показывает статус оцифровки как один
  из четырёх компонентов общей готовности.
- Статус `rejected`/`pending_review` **не блокирует** просмотр, QC,
  интерпретацию и т. п. — ограничение действует только на итоговый экспорт.

## 6. Просмотр каротажа (Каротаж)

Открывается по умолчанию при запуске (вкладка **Каротаж** в верхнем меню
или клавиша `1`).

### 6.1 Треки и загрузка

После выбора скважины и рейса GeoLog автоматически рисует треки кривых по
глубине на Canvas-полотне и **сразу обрезает вид по интервалу, где у кривых
реально есть данные** (не по номинальному интервалу LAS-заголовка) — так
не тратится время на прокрутку пустых участков вверху/внизу файла.

### 6.2 Масштаб и единицы

В панели инструментов (кнопка **Advanced**, чтобы показать
дополнительные элементы):
- **Scale** — вертикальный масштаб отображения: `1:250`, `1:500` (по
  умолчанию), `1:1000`.
- **Units** — единицы глубины: `Native` (как в LAS), `Metric`, `Imperial`.
- **Perf** — режим прореживания данных (децимация) для очень длинных кривых:
  включите чекбокс и задайте максимум точек (по умолчанию 3000) — ускоряет
  отрисовку на медленных машинах ценой визуального сглаживания деталей.

### 6.3 Навигация

- **Колесо мыши над треками** — зум по глубине.
- **Перетаскивание (drag)** — панорамирование вверх/вниз.
- Поля **Top / Bottom** в панели инструментов — ручной ввод границ видимого
  интервала.
- Кнопка **К данным** (крестик-прицел) — заново обрезать вид по фактическому
  интервалу данных загруженных кривых (то же самое, что происходит
  автоматически при первой загрузке).
- `Home` / `End` — перейти к верхней/нижней границе скважины,
  `+`/`-` — зум, `↑`/`↓` — панорамирование (см. раздел
  [23](#23-горячие-клавиши)).

### 6.4 Литология

Кнопка **Lithology** (или клавиша `L`) включает/выключает дополнительный
трек литологии. Параметры классификации — в блоке **Advanced**:
- **GR Min / GR Max** — границы гамма-каротажа для условной шкалы «песок —
  глина»;
- **Method** — метод определения литологии: `GR+RHOB+NPHI` (по умолчанию),
  `Crossplot`, `GR only`.

### 6.5 Сравнение рейсов (Overlay)

Кнопка **Overlay** открывает панель сравнения двух рейсов одной кривой:
1. Выберите **Run A** и **Run B** (например, старая и новая оцифровка) и
   кривую для сравнения.
2. Настройте цвет и прозрачность рейса B.
3. Включите **Show Difference**, чтобы увидеть разность значений, либо
   нажмите **Run Diff** для численного сравнения рейсов.

### 6.6 Режим редактирования кривой

Кнопка **Edit Mode** включает интерактивное редактирование точек кривой:
1. Включите Edit Mode, выберите кривую в поле **Edit Curve**.
2. Кликните по точке на треке — откроется всплывающее поле для ввода нового
   значения (пустое значение = NULL).
3. Индикатор **No unsaved edits** меняется на счётчик несохранённых правок;
   кнопки **Save** / **Cancel** фиксируют или отменяют правки.
4. История правок кривой видна в нижней панели **Curve Edit History**
   (кнопка **Details** показывает/скрывает нижние панели: Curves, Formation
   Tops, Zones, Curve Edit History).

### 6.7 Полноэкранный режим

Клавиша `F` переключает полноэкранный режим просмотра трека (максимум места
под каротаж, без сайдбара и панелей).

## 7. Мнемоники

Вкладка **Мнемоники** в верхнем меню (тултип: «Проверка и унификация
мнемоник»). Приводит «сырые» (вендорские) названия кривых к каноническим
мнемоникам (например `ZDEN → RHOB`, `ГК → GR`, `MYRES → RT`).

### 7.1 Сканирование скважины

1. Откройте вкладку **Мнемоники**, выберите скважину в сайдбаре.
2. Нажмите **Scan** — таблица покажет по каждой кривой: сырое имя,
   предполагаемую каноническую мнемонику, метод (семейство), **уровень
   уверенности** (0.0–1.0) и обоснование (`Basis`).
3. Порог `Min confidence` определяет, какие строки будут отмечены галочкой
   для применения:
   - `1.0` — только точные совпадения по встроенному словарю;
   - `0.9` (по умолчанию) — точные + известные варианты написания;
   - `0.6` — включая нечёткие (fuzzy) совпадения по ключевым словам.
4. Кривые, уже имеющие каноническое имя, помечаются отдельно и не
   переименовываются повторно.

### 7.2 Применение

**Требуется роль interpreter или admin.**
- **Apply selected** — применить только отмеченные галочками строки.
- **Auto-apply all** — применить все строки, прошедшие порог уверенности,
  выбранный в `Min confidence`.

После применения интерфейс перезагружает данные скважины, чтобы просмотр
каротажа и другие панели сразу увидели новые канонические имена. Операция
идемпотентна — повторный запуск не переименует уже канонические кривые
дважды и не создаёт конфликтов имён.

### 7.3 Собственные соответствия (custom aliases)

В верхней части панели — таблица пользовательских соответствий
«сырое имя → канонический код»:
1. Введите вендорскую мнемонику и выберите канонический код из списка →
   **Add**.
2. Массовый импорт: **Import Excel/CSV** — загрузите двухколоночный файл
   (`raw`, `canonical`) в формате `.xlsx`/`.xlsm`/`.csv`/`.tsv`; чекбокс
   **replace all** заменяет весь текущий набор пользовательских
   соответствий вместо добавления к нему. Кнопка **Template** скачивает
   образец CSV с нужными заголовками.
3. Пользовательские соответствия имеют приоритет над встроенным словарём
   везде — при парсинге LAS, при авто-подборе мнемоник и на карте охвата.
4. Встроенный словарь (100+ пар) можно посмотреть, раскрыв **Show built-in
   defaults**.
5. Удаление своего соответствия — кнопка «✕» в строке таблицы.

## 8. Дубли кривых и дубли исследований

Вкладка **Дубли кривых** в верхнем меню (тултип: «Проверка кривых на полное
дублирование»). Решает две разные задачи:

### 8.1 Дубли кривых (побайтовое совпадение значений)

Ищет пары кривых, значения которых **полностью совпадают** на общем
интервале глубин (например, один и тот же ГИС записан дважды под разными
мнемониками, либо файл случайно загружен повторно под другой скважиной).
Численно похожие, но не идентичные кривые одного семейства (например,
градиент-зонды БКЗ `GZ1..GZ5`) под это определение не подпадают.

1. Откройте вкладку **Дубли кривых**.
2. Выберите **Область**: `Текущая скважина` или `Весь проект (включая между
   скважинами)`.
3. Нажмите **Проверить**.
4. Таблица результатов показывает пару кривых (скважина/рейс/файл/мнемоника/
   единицы), число совпавших точек, процент покрытия и отдельно помечает
   совпадения **между разными скважинами** — это более серьёзный сигнал
   (возможен файл, случайно загруженный не в ту скважину).

**Если в проекте очень много кривых** (порог — 3000 «сырых» строк кривых по
всем скважинам), полное попарное сравнение по всему проекту **пропускается**
для защиты от многоминутного зависания запроса. В этом случае в строке
итогов над таблицей вы увидите `... · null дублей` вместо числа, а сама
таблица останется пустой — это **не значит, что дублей нет**, значит, что
проверку нужно делать по каждой скважине отдельно (переключить область на
`Текущая скважина`).

### 8.2 Дубли исследований (по скважине/площади/интервалу глубин)

Отдельная, более грубая проверка на уровне **исследования** (study), а не
значений кривых — включается автоматически при выборе области **«Весь
проект»** и показывается ниже основной таблицы, в блоке **«Дубли
исследований»**.

Ловит два сценария, которые побайтовая проверка кривых пропускает (потому что
значения там не совпадают буквально):
- тот же рейс оцифрован повторно другим оператором/проходом OCR — числа
  чуть отличаются, но скважина, интервал глубин и набор методов те же;
- одна и та же скважина заведена в системе дважды под разными вариантами
  написания имени (например «105», «Скв. 105», «105-Б»).

Поскольку в исходных данных обычно нет UWI, сравнение идёт по: имени
скважины (после нормализации написания), площади, пересечению интервала
глубин и общим методам каротажа рейсов. Для каждой найденной пары в таблице
показаны: обе скважины, доля пересечения интервала глубин, доля общих
методов, список общих методов и причина совпадения (тот же well /
разные скважины с одинаковым именем / разные скважины одной площади).

Эта проверка **не заменяет** проверку дублей кривых из [8.1](#81-дубли-кривых-побайтовое-совпадение-значений)
— это дополнительный, более грубый сигнал.

## 9. QC — контроль качества

Вкладка **QC** в верхнем меню (тултип: «Контроль качества: пропуски,
выбросы»), либо клавиша `5`.

1. Выберите скважину и рейс, откройте вкладку **QC**.
2. Панель автоматически считает по каждой загруженной кривой:
   - **Total / Valid** — всего точек / валидных (не NULL) точек;
   - **Missing %** — доля пропусков;
   - **Outlier %** — доля выбросов (значения, отклоняющиеся от среднего
     больше чем на 3 стандартных отклонения);
   - **Mean / Std** — среднее и стандартное отклонение по валидным точкам;
   - **Reliability** — метка `HIGH` / `MEDIUM` / `LOW`:
     - `LOW`, если пропусков > 20% или выбросов > 8%;
     - `MEDIUM`, если пропусков > 8% или выбросов > 4%;
     - иначе `HIGH`.
3. Сверху — сводка: количество кривых по каждому уровню надёжности,
   предупреждение о слишком малой выборке (< 30 валидных точек по кривой),
   список обнаруженных аномалий (риск размыва ствола по среднему CAL,
   расхождение глубинного/бокового сопротивления и т. п.), список длинных
   пропусков по глубине, итоговая **QC-оценка** (буква A/B/C и балл 0–100)
   и текстовые рекомендации (например, «повторно обработать кривые низкого
   качества» или «заполнить/пометить длинные пропуски перед оценкой
   net pay»).

QC не требует особой роли — доступно для просмотра всем ролям, включая
`viewer`.

## 10. Инклинометрия

Вкладка **Инклинометрия** в верхнем меню (тултип: «Инклинометрия: DLS,
проекции, дубли, заметки»).

1. Выберите скважину — если для неё загружен инклинометрический замер,
   панель покажет:
   - карточки сводки: число замеров, забой по стволу (MD) и по вертикали
     (TVD), отход от устья, максимальный зенитный угол, максимальный DLS
     (интенсивность искривления, °/10 м) и число дублей замеров;
   - **вертикальную проекцию** (отход — TVD);
   - **план сверху** (восток — север);
   - **профиль DLS по глубине** с порогом.
2. Порог DLS задаётся полем **Порог DLS, °/10м** (по умолчанию 20) —
   интервалы выше порога подсвечиваются красным на всех трёх графиках.
3. Список **выявленных проблем** под графиками показывает конкретные
   замечания (превышение DLS, дубли и т. п.) с уровнем серьёзности.
4. Кнопка **Пересчитать** — обновить расчёты (например, после изменения
   порога DLS).
5. Кнопка **Удалить дубли** (**требуется роль interpreter или admin**) —
   убирает повторяющиеся замеры инклинометрии по глубине.

### 10.1 Заметки по качеству

В нижней части вкладки — журнал заметок по качеству данных скважины (не
только инклинометрии):
1. Введите текст, при необходимости — название кривой и уровень серьёзности
   (низкая/средняя/высокая) → **Добавить**.
2. **Авто-заметки по QC** — автоматически создаёт заметки на основе
   результатов QC-проверки.
3. Каждую заметку можно удалить кнопкой «✕» в её строке; в таблице видно,
   создана ли заметка вручную или автоматически.

## 11. Карта охвата ГИС и опись исследований

Вкладка **Охват ГИС** в верхнем меню (тултип: «Карта охвата ГИС: по
скважинам, глубине и горизонтам»). Один раздел с четырьмя режимами
(переключатель **Вид**):

### 11.1 Матрица (скв. × метод)

По умолчанию открывается матрица «скважина × метод каротажа»: строки —
скважины проекта, столбцы — распознанные методы (сгруппированы по категории:
электрические, радиоактивные, акустические и т. д.). Ячейка окрашивается по
интенсивности в зависимости от выбранного режима **Показ**:
- `Охват по глубине` — доля интервала скважины, покрытая замером;
- `Заполненность` — доля валидных (не NULL) значений внутри покрытого
  интервала;
- `Только наличие` — просто есть/нет метода.

Наведите курсор на ячейку — всплывающая подсказка покажет процент охвата,
интервал глубин и список исходных мнемоник. Чекбокс **только замеры**
скрывает расчётные (derived) кривые, оставляя только реально измеренные.

### 11.2 Планшет по глубине

Режим **Планшет по глубине** рисует по каждой скважине вертикальную полосу
из закрашенных столбцов-методов вдоль общей шкалы глубин — быстро видно,
какие интервалы каких скважин покрыты какими методами. Пунктирными линиями
поверх наносятся отбивки (горизонты), если они заведены хотя бы для одной
скважины. Если в интервале присутствуют ≥2 кривых одного метода —
столбец закрашивается штриховкой другого цвета (см. легенду под графиком).

### 11.3 Таблица по горизонтам

Режим **Таблица по горизонтам** требует, чтобы для скважин были заведены
отбивки (раздел [12](#12-отбивки-и-горизонты)) — иначе таблица пустая с
подсказкой их загрузить. Для каждой пары «скважина — горизонт» показывает
кровлю, подошву, мощность и по каждому методу — есть ли запись в этом
интервале горизонта, число кривых (`+N`, если больше одной) и процент
покрытия мощности горизонта записью.

Экспорт таблицы: кнопки **Экспорт XLSX** / **Экспорт CSV** в панели
инструментов.

### 11.4 Опись исследований (Registry)

Режим **Опись исследований** — сверка внешнего Excel/CSV-реестра «что
должно быть исследовано» с тем, что реально загружено в GeoLog.

**Импорт описи:**
1. Переключите **Вид** на `Опись исследований`.
2. Нажмите **Импортировать опись** и выберите файл `.xlsx`/`.xlsm`/`.xltx`/
   `.csv`/`.tsv`. Ожидаемые столбцы (заголовки на русском или английском,
   порядок и точное написание не важны, определяются по синонимам):
   `скважина`/`well`, `площадь`/`field`, `вид исследования`/`study`,
   и глубины — либо `глубина от`/`глубина до` (`top`/`bottom`), либо один
   объединённый столбец `глубины`/`интервал` вида `1000-1200`.
3. Чекбокс **заменить** — очистить ранее загруженную опись перед импортом
   (иначе новые строки добавляются к уже существующим).
4. После импорта таблица сразу показывает результат сверки с базой.

**Как считается совпадение (`match_status`)** — сверка идёт **не по UWI**
(в исходных данных его обычно нет), а по имени скважины (после нормализации
написания — регистр, «скв.», «№», разделители игнорируются), затем:
- если по имени скважина найдена, но в строке описи не указан интервал
  глубин — статус `найдено` (имени достаточно);
- если интервал указан — ищется рейс этой скважины, максимально
  пересекающийся по глубине; если пересечение ≥ 50% — статус `найдено`, если
  скважина есть, но подходящего по глубине рейса нет — `скважина есть,
  интервал не совпадает`;
- если скважина с таким именем вообще не найдена — `не найдено`.

Для каждой строки таблица также показывает найденный рейс и его статус
оцифровки (см. раздел [5](#5-проверка-оцифровки-digitization-review)).

**Ручная пометка (`action_status`)** — отдельно от автоматически вычисляемого
`match_status`. Для строк со статусом `не найдено` доступна кнопка
**«📤 Отправить на оцифровку»** — она не меняет результат сверки, а просто
фиксирует, что по этой позиции уже сделан запрос во внешнюю группу
оцифровки (полезно при повторной проверке описи, чтобы отличать «уже
запрошено» от «ещё не обработано»); отменить пометку — кнопка со стрелкой
рядом. **Требуется роль interpreter или admin.**

## 12. Отбивки и Горизонты

### 12.1 Отбивки (управление по одной скважине)

Вкладка **Отбивки** в верхнем меню (тултип: «Отбивки (горизонты): создание,
импорт, экспорт»).

1. Выберите скважину.
2. **Add Top** — добавить отбивку вручную (название горизонта, глубина
   кровли, при необходимости глубина подошвы, цвет, литология).
3. **Export CSV** / **Petrel CSV** — выгрузить отбивки текущей скважины в
   CSV (второй вариант — в формате, совместимом с Petrel).
4. **Import CSV** — загрузить отбивки из CSV-файла для текущей скважины.

Отбивки, добавленные здесь, сразу видны в просмотре каротажа (трек глубины)
и используются в корреляции, карте охвата по горизонтам и т. д. Добавление,
редактирование и удаление отбивки — отменяемые действия (раздел
[21](#21-отмена--повтор-действий-undoredo)).

Быстрое добавление отбивки прямо на треке: в шапке скважины откройте меню
**Interpret** → **Add Top**, либо (если включено в текущей версии трека)
двойной клик по нужной глубине на канвасе каротажа.

### 12.2 Горизонты (сводная таблица по проекту)

Вкладка **Горизонты** в верхнем меню (тултип: «Таблица горизонтов по всем
скважинам»).

1. Нажмите **Load** — построится сводная матрица: по строкам — горизонты,
   по столбцам — скважины проекта (или наоборот, в зависимости от числа
   горизонтов/скважин), в ячейках — глубина присутствия горизонта в каждой
   скважине.

Используется для быстрой сверки полноты отбивок по всему фонду скважин
проекта — сразу видно, в каких скважинах горизонт не заведён.

## 13. Сопоставление скважин (корреляция)

Вкладка **Сопоставление** в верхнем меню (тултип: «Сопоставление скважин по
кривым и отбивкам»).

1. Выберите **Reference Well** (опорная скважина) и **Compare Well**
   (сравниваемая), а также **Curve** для сопоставления (GR, RT, NPHI, RHOB).
2. Нажмите **Render** — обе кривые отрисуются рядом по общей шкале глубин;
   чекбокс **Show Tops** накладывает отбивки обеих скважин.
3. **Ручной сдвиг**: поля **Depth Shift (ft)** и **Stretch** сдвигают/
   растягивают кривую сравниваемой скважины относительно опорной.
4. **Auto Tie** — автоматический подбор сдвига по взаимной корреляции кривых
   (кросс-корреляция), без ручного подбора.
5. **Top Snap** — притянуть отбивки сравниваемой скважины к ближайшим
   похожим уровням опорной.
6. **Name Tie** — связать отбивки по совпадающим названиям горизонтов.
7. **Pick Marker** — режим ручной расстановки маркеров-меток соответствия на
   обеих кривых кликом мыши; таблица подобранных маркеров показывается под
   графиком.
8. **Apply Median Shift** / **Apply Mean Shift** — применить сдвиг,
   вычисленный как медиана/среднее по расставленным маркерам.
9. **Clear Markers** — очистить расставленные маркеры.
10. **Save Profile** (**требуется роль interpreter или admin**) — сохранить
    текущие настройки корреляции (сдвиг/растяжение/маркеры) как профиль для
    этой пары скважин.

## 14. Зоны, петрофизика и шаблоны

Панель **Petrophysics** не вынесена в верхнее меню этой сборки, но
полностью доступна двумя способами:
- нажать `4` (если фокус не в текстовом поле);
- открыть палитру команд `Ctrl/Cmd+K`, начать вводить «Petrophysics» и
  выбрать пункт.

### 14.1 Модель насыщенности и параметры

1. Выберите модель в **Saturation Model**: Archie, Simandoux, Indonesian,
   Waxman-Smits, Dual-Water.
2. Задайте параметры Арчи: `a` (извилистость), `m` (цементация), `n`
   (показатель насыщения), `Rw` (сопротивление пластовой воды, ом·м).
3. Задайте отсечки (**Cutoffs**): `Vsh max`, `PHIE min`, `Sw max` — по ним
   считается чистый нефтенасыщенный интервал (net pay).
4. **Calculate** — рассчитать Sw, Vsh, PHIE по загруженным кривым текущей
   скважины и показать результат справа.
5. Дополнительные расчёты доступны отдельными кнопками: **Compute Sw
   (API)**, **Dual-Water**, **Multimineral**, **Permeability Multi**, **Vcl
   Enhanced** — требуют роли `interpreter` (кнопки визуально неактивны для
   `viewer`).
6. **Save Params** (**требуется роль interpreter или admin**) — сохранить
   параметры расчёта для скважины.

### 14.2 Зоны

- **Zone Stats** — статистика по зонам скважины (валовая/чистая мощность,
  средние свойства).
- **Auto Zone from Tops** — автоматически построить зоны из уже заведённых
  отбивок.
- **Full Report** — сводный отчёт по зонам (валовая/чистая мощность,
  средние свойства по зонам) для скачивания.
- **Zonation CSV** (**Export Zonation Report**) — то же в формате CSV.

Добавить зону вручную можно также из шапки скважины: меню **Interpret** →
**Add Zone**; список зон отображается в нижней панели **Zones** (кнопка
**Details** в панели инструментов каротажа). Добавление зоны — отменяемое
действие (раздел [21](#21-отмена--повтор-действий-undoredo)).

### 14.3 Шаблоны интерпретации (workflow templates)

Блок **Workflow Templates** предлагает готовые наборы параметров (карточки)
под типовую литологию — выбор карточки подставляет параметры модели и
отсечки в форму, с предпросмотром изменений в блоке над карточками.

**Подпись шаблона (Template Signature)** — механизм QA-фиксации набора
параметров:
- **Lock Template Signature** (**требуется роль interpreter или admin**) —
  зафиксировать текущий набор параметров/шаблона как подписанный QA;
  строка **Template lock status** покажет, что параметры заблокированы, кем
  и когда.
- **Unlock Template Signature** (**требуется роль admin**) — разблокировать
  подписанный шаблон может только `admin`; для `interpreter` и `viewer`
  кнопка неактивна (в отличие от Lock, где `interpreter` тоже допускается) —
  снять QA-подпись сложнее, чем поставить, это сделано намеренно.

## 17. Сводка готовности скважины

Справа от кнопок Accept/Reject в шапке скважины появляется небольшой цветной
виджет (после выбора скважины) — это сводка **готовности к сдаче**,
собирающая в одном запросе четыре независимые проверки:

1. **Подпись/QC/оцифровка** (`locked`, `qc_rating`) — подписана ли скважина
   утверждённым снапшотом интерпретации (раздел
   [18](#18-подпись-sign-off-и-экспорт)), не является ли расширенная
   QC-оценка `POOR`, и все ли рейсы с кривыми прошли проверку оцифровки
   (раздел [5](#5-проверка-оцифровки-digitization-review)) — без «зависших»
   `pending_review`/необработанных `rejected`.
2. **Дубли кривых** — есть ли для этой скважины найденные дубли кривых
   (раздел [8.1](#81-дубли-кривых-побайтовое-совпадение-значений)).
3. **Дубли исследований** — участвует ли скважина хотя бы в одной паре
   «дублей исследований» на уровне проекта (раздел
   [8.2](#82-дубли-исследований-по-скважинеплощадиинтервалу-глубин)).
4. **Полнота описи** — сколько строк описи исследований, относящихся к этой
   скважине, реально нашли соответствие в базе (раздел
   [11.4](#114-опись-исследований-registry)).

**Значки на виджете:** `QC: …`, `Дубли: N` (сумма дублей кривых и
исследований), `Опись: сопоставлено/всего`, и `🔒 подписано` /
`🔓 не подписано`.

**Цвет виджета:**
- зелёный — все четыре проверки в порядке, скважина готова к сдаче;
- красный — QC-оценка `POOR` либо скважина не подписана;
- жёлтый — подписана и QC в порядке, но остались другие замечания (дубли,
  неполная опись и т. п.).

Кликните по виджету — откроется всплывающий список конкретных замечаний
(«no issues — ready for handoff», если всё чисто, либо перечень найденных
проблем текстом).

## 18. Подпись (sign-off) и экспорт

### 18.1 Что означает «подписана» (locked)

Экспорт скважины (LAS, полный пакет и т. п.) в этой сборке **заблокирован
по умолчанию для любой новой скважины**, пока для неё не оформлена подпись:
утверждённый снапшот интерпретации (formation tops + zones + параметры
петрофизики на момент подписи). После утверждения снапшота скважина
переходит в состояние **`locked`** — и дальнейшие изменения данных этой
скважины для ролей `viewer`/`interpreter` блокируются (см. раздел
[2.1](#21-блокировка-скважины-locked)), пока `admin` не снимет блокировку.

**В текущей версии интерфейса создание и утверждение снапшота (сама
операция подписи) не вынесены в отдельную кнопку интерфейса** — сохранить
их можно только через API/Swagger (`http://localhost:8000/docs`), ролью
`interpreter` или `admin`:

1. Создать снапшот (фиксирует текущие отбивки/зоны/параметры петрофизики
   скважины):
   `POST /api/wells/{id}/snapshots` — тело запроса можно оставить пустым
   или передать `{"label": "..."}`.
2. Утвердить снапшот (`{id}` скважины, `{snapshot_id}` — из ответа
   предыдущего запроса), заголовок `X-User-Role: interpreter` (или
   `admin`):
   `POST /api/wells/{id}/snapshots/{snapshot_id}/approve`
   — после этого скважина переходит в состояние `locked`.
3. Проверить статус блокировки в любой момент:
   `GET /api/wells/{id}/lock-status`.
4. Снять блокировку может только `admin`:
   `POST /api/wells/{id}/unlock`.

(Кнопки **💾 Save Session** / **📂 Load Session** в верхней панели к этому
механизму отношения не имеют — они лишь сохраняют/загружают локальный
JSON-файл с настройками просмотра и параметрами петрофизики в браузере, а
не утверждают снапшот на сервере.)

### 18.2 Экспорт — что чем блокируется

Четыре эндпоинта экспорта требуют, чтобы скважина была подписана
(`locked`), QC-оценка не была `POOR`, и все рейсы с кривыми были приняты по
результатам проверки оцифровки: **LAS-экспорт**, **экспорт-пакет** (JSON),
**экспорт клиентского пакета (bundle)** и **delivery-bundle**. Если хотя бы
одно условие не выполнено — сервер вернёт ошибку **409** с подробным
списком причин и подсказкой, что делать.

Кнопки в интерфейсе:

| Кнопка | Где | Что делает |
|---|---|---|
| **Export → LAS File** (шапка скважины) / **Export LAS** (верхняя панель, значок ⬇, `Ctrl/Cmd+E`) | LAS текущего активного рейса скважины (с наибольшим числом точек) | Гейт подписи применяется |
| **Export → Summary CSV** | Сводка интервалов net pay/QC, посчитанная **на клиенте** из данных, уже загруженных в просмотрщике | **Гейт подписи НЕ применяется** — это локальный расчёт, не защищённый эндпоинт |
| **Export → Report PDF (Pro)** / кнопка **downloadReportPDF** | Отчёт PDF (раздел [22](#22-отчёт-pdf)) | Гейт подписи НЕ применяется |
| **Export → Full Package** | JSON-пакет по скважине (`export-package`) + локально добавленные данные интерпретации/маркеров корреляции | Гейт подписи применяется |
| **📦 Package Export** (верхняя панель) | Экспортирует CSV отбивок по всем скважинам проекта, затем по очереди LAS каждой скважины проекта; скважины, заблокированные гейтом подписи, пропускаются, и в сводке явно указывается, какие скважины пропущены | Гейт подписи применяется к LAS-части, по скважинно |
| **📊 Report/Plot Export (SVG)** | Векторный SVG текущего вида трека каротажа (для печати/вставки в отчёт) | Гейт подписи не применяется |

### 18.3 Обход гейта (`force=true`)

Каждый из четырёх защищённых эндпоинтов принимает параметр строки запроса
`?force=true`, который пропускает проверку подписи (само обращение при этом
всё равно фиксируется в журнале аудита с пометкой `force=True` и перечнем
проигнорированных проблем). **В интерфейсе кнопки этот параметр не
выставляют** — обойти гейт можно только прямым обращением к API (например,
через `/docs` или `curl`), например:

```
GET /api/wells/{id}/export-las?force=true
```

Технически этот параметр не ограничен ролью на уровне сервера (эндпоинты
экспорта — `GET`-запросы, для которых ролевая проверка на запись не
применяется), но использовать его в обход обычного процесса подписи —
осознанное решение, и оно полностью видно в журнале аудита.

## 19. Журнал аудита

Панель **Audit Trail** не вынесена в верхнее меню, но доступна через
палитру команд: `Ctrl/Cmd+K` → **Audit Trail**.

1. Откройте палитру команд и выберите **Audit Trail** (или нажмите
   **Refresh** в открывшейся панели).
2. Список показывает последние действия по проекту: загрузки, расчёты,
   правки, экспорты — с типом действия, временем и подробностями.

### 19.1 Что логируется и зачем нужна цепочка хэшей

Каждая успешная операция записи (`POST`/`PUT`/`DELETE` к `/api/...`)
автоматически добавляет запись в журнал аудита: кто (роль), что, когда,
какой путь API, какой статус ответа. Каждая запись хранит хэш **самой себя**
и хэш **предыдущей** записи — это выстраивает записи в непрерывную цепочку.
Смысл на практике: если кто-то задним числом изменит или удалит запись в
базе журнала, пересчитанная цепочка «развалится» на этом месте — то есть
**систему можно проверить на то, что история не подделана**, без
необходимости разбираться в деталях криптографии.

### 19.2 Проверка целостности и подписанный экспорт

Через API (Swagger `/docs`):
- `GET /api/audit-log/verify?limit=2000` — пересчитывает цепочку по
  последним N записям и возвращает `{"ok": true/false, "issues": [...]}`
  — список конкретных несовпадений, если цепочка нарушена.
- `GET /api/audit-log/immutability-status` — проверяет, что в базе данных
  включены триггеры, физически запрещающие `UPDATE`/`DELETE` по таблице
  журнала (защита на уровне СУБД, а не только приложения).
- `GET /api/audit-log/verify/export?sign=true&kid=<ключ>` — экспортирует
  отчёт о проверке цепочки вместе с криптографической подписью
  (HMAC-SHA256) — такой файл можно передать третьей стороне (аудитору,
  заказчику), и она сможет убедиться, что отчёт не подделан задним числом,
  без доступа к самой базе. Ключи подписи настраиваются переменными
  окружения (`AUDIT_EXPORT_HMAC_KEYS_JSON`, `AUDIT_EXPORT_HMAC_ACTIVE_KID`)
  — см. `README.md`, раздел «Audit Signature Verification Contract».
- Проверить подпись отдельно: `GET`/`POST /api/audit-log/verify/signature`.

Эти операции выполняются через `/docs` (Swagger) или `curl` — отдельной
кнопки «проверить подпись» в веб-интерфейсе нет.

## 21. Отмена / повтор действий (Undo/Redo)

Кнопки **Undo** / **Redo** — в шапке скважины, меню **Interpret**, либо
горячие клавиши `Ctrl/Cmd+Z` (отменить) и `Ctrl/Cmd+Y` /
`Ctrl/Cmd+Shift+Z` (повторить).

Стек отмены **локальный для текущей сессии браузера** (не сохраняется на
сервере и не переживает перезагрузку страницы) и поддерживает следующие
действия:
- добавление / удаление / редактирование формационной отбивки (Top);
- добавление / удаление заметки-аннотации;
- добавление зоны.

Каждое действие технически отменяется реальным обратным вызовом к API
(например, отмена добавления отбивки — это её настоящее удаление через
`DELETE /api/tops/{id}`), поэтому Undo/Redo работает и в многопользовательском
режиме предсказуемо — как обычное действие того же пользователя, а не
локальный откат интерфейса.

   по умолчанию отчёт генерируется со стандартным шаблоном `professional` и
   обоими разделами включёнными.
4. PDF скачивается автоматически.

**Содержимое отчёта:** шапка (оператор, название скважины, дата
формирования, логотип проекта — если загружен), список отбивок, статистика
по зонам и применённые отсечки (Vsh/PHIE/Sw), список рейсов скважины,
сохранённые параметры петрофизики, и опционально — сводка по кривым и
снимок текущего состояния QC. Формируется без требования подписи скважины
(гейт экспорта из раздела [18](#18-подпись-sign-off-и-экспорт) на PDF-отчёт
не распространяется).

## 23. Горячие клавиши

Полный список открывается прямо в приложении: кнопка **❓** в верхней
панели или клавиша **`?`**.

**Переключение вкладок** (работает и для панелей, не показанных в верхнем
меню этой сборки — Cross Plot, Pickett, Petrophysics, Sensitivity, Facies):

| Клавиша | Раздел |
|---|---|
| `1` | Каротаж (Log Viewer) |
| `2` | Cross Plot |
| `3` | Pickett Plot |
| `4` | Petrophysics |
| `5` | QC |
| `6` | Статистика |
| `7` | Сопоставление (Correlation) |
| `8` | Sensitivity |
| `9` | Facies |

**Навигация по каротажу:**

| Клавиша | Действие |
|---|---|
| `↑` / `↓` | Панорамирование по глубине вверх/вниз |
| `+` / `=` | Приблизить |
| `-` | Отдалить |
| `Home` / `End` | Перейти к верху / низу скважины |
| `F` | Полноэкранный режим просмотра |
| `L` | Показать/скрыть трек литологии |
| `D` | Показать/скрыть нижние панели (Details) |
| `A` | Автомасштаб / автообрезка по данным |

**Редактирование:**

| Клавиша | Действие |
|---|---|
| `Ctrl/Cmd+Z` | Undo |
| `Ctrl/Cmd+Y` или `Ctrl/Cmd+Shift+Z` | Redo |
| `Ctrl/Cmd+S` | Сохранить аннотации |
| `Ctrl/Cmd+E` | Экспорт LAS |
| `Ctrl/Cmd+U` | Загрузить LAS |

**Общее:**

| Клавиша | Действие |
|---|---|
| `Esc` | Закрыть модальное окно / палитру команд / выпадающее меню |
| `?` | Открыть список горячих клавиш |
| `Ctrl/Cmd+K` | Открыть палитру команд (поиск по всем разделам и действиям, включая скрытые из верхнего меню) |

Дополнительно (не показаны во встроенной справке, но работают, если фокус не
в текстовом поле): `V` — переключить авто-литологию, `C` — оверлей керна,
`T` — режим выбора глубины на линейке, `G` — легенда кривых, `B` — линии
отбивок, `E` (без Ctrl) — метрики отрисовки, `R` (без Ctrl) — принудительно
перерисовать вид.
